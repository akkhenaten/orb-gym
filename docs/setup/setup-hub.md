## First owner and resume

Verified signup establishes the retry-safe owner/workspace context. Limited bootstrap lets the actual owner enrol supported privileged authentication/recovery and complete their own onboarding without requiring already-enrolled MFA to reach the enrolment screen. Until required assurance exists, no privileged customer-data/finance/global export/support access is exposed. Auth capability and actual verification/invitation delivery are platform implementation prerequisites; owner setup cannot bypass a broken provider by ticking complete.

The owner enters a persistent setup hub with selected company/gym, optional capability choices, section status, named responsible person/queue, blockers, pending review/evidence and Continue action. Show actual server-saved time/version separately from local edits. Resume the same authorised context after sign-in/refresh; no duplicates on repeated account/workspace/gym/section submission. User can browse permitted sections in any useful order. Section dependencies are contextual prerequisites, not a compulsory sixteen-step linear wizard.

Company name/details and first gym are requested at the appropriate onboarding stage; later Add gym reuses the same hub scoped to that location. Default Orb Gym Basic and original logo are valid without custom branding. Optional coach/PT/trial/junior/import/POS features can remain disabled without blocking unrelated ready operations. Show selected/not selected separately from incomplete/blocked; no false global 100percent calculation over unselected optional features.

## Screen structure and actions

Setup overview: company/gym scope selector, resume card, sections with status/owner/missing item count and a capability readiness panel. Actions are Continue, Assign section where delegated, View blockers, Review evidence and Go to module. Each blocker identifies exact current required field or evidence, affected capability, safe reason, actual source settings link and authorised resolver; restricted provider/HR/health details are redacted while the correct owner/queue remains visible.

Section detail links/embeds the owning settings/form/workflow; it is not a second database of policy values. Save draft never publishes appearance, activates membership, sends invitation or makes a paid service live. Review/readiness uses current source records; a setup completion checkmark cannot bypass source signature/approval/collection/qualifications. Final review summarises capabilities enabled/ready/blocked/unselected, current source versions/evidence and next owners. Enabling each real service invokes that module's existing authorised publish/activation command. No extra ceremonial confirmation before every already authorised routine action.

Desktop: left company/gym nav, Setup entry under company/gym Settings and an onboarding shortcut on dashboard; selected section list and details/readiness panes if inner width permits. Tablet/iPad/mobile: bottom nav retained, Setup reached through More/Settings, Overview/Sections/Readiness views with full-route section forms. Keep drafts/selected scope during reflow; errors/keyboard/action footer remain reachable. A banner may summarise incomplete relevant setup without blocking all ordinary pages.

## Delegation and ownership

Owner/platform admin can assign sections to actual authorised people/queues; senior management follows assigned gyms/company grants, local manager only their gym, specialists receive only applicable source access. Assignment is responsibility, not a permission grant or delegation of professional competence. If the assignee lacks source authority, display Needs access/assign an authorised resolver; owner can separately use existing role/user access controls. Section due dates/reminders are optional explicit company settings, not invented deadlines.

Assignee can view only their safe progress/source details. Changing assignee/revoking scope stops obsolete reminders and re-evaluates current source access. Inactive/leaving assignee leaves a visible owner queue, not an orphan task. Section reviewer, content/professional reviewer, business approver and actual signatory remain separate. A setup evidence review cannot approve health questionnaires, refunds, quotes, contracts or public publication by implication.

## Readiness model

Section progress tracks authoring/responsibility; capability readiness is computed from current configuration, selected service mode, actual provider/runtime evidence, business eligibility and permissions. Record exact source/policy/evaluation versions/as-of, missing/invalid dependencies and next owner. No editable is_ready=true flag. Re-evaluate at actual source publish/activation/command and on material dependency changes; a cached green status cannot grant stale access.

Examples: asset preparation is independent of merchant setup; rota drafts are independent of a custom logo; a public information page can publish while paid plans remain unbookable. A live paid class needs its exact collection/issuer/capacity/coach/terms gates, while an external rental-coach class follows its different approved mode. In-app/source action state remains visible even if optional external reminder automation is unconfigured. First-time auth/invite/recovery delivery is separately mandatory before actual onboarding can work.

Missing setup blocks only affected command, but do not falsely allow dependencies: a ready template cannot be signed if signature capability/source authority is missing; a ready member account cannot enter without effective service grant; stock preparation does not prove tender. Missing reporting cost basis leaves profit/valuation unavailable while known permitted operational metrics remain available.

When current live setup changes, mark Needs revalidation and identify actual future/live impacts. Do not blindly disable everything, erase history or continue using unsafe stale values. Apply existing source policies for restrictions, review-first adverse payments and manager-led paid-service disruption. Existing commitments/issued agreements/receipts remain owned and frozen. Missing approval backup means pending/blocked owner queue, never automatic approval.

## Evidence and source-of-truth ownership

Platform implementation evidence includes actual project/auth/file/job/email/payment/device/provider tests, assurance/recovery and restore/performance/accessibility checks. Company setup evidence includes approved forms/terms, legal issuer, role choices, services/prices, current agreement/credential review and published policy values. These are different evidence classes. Uploaded screenshot, payment proof or administrator checkbox alone does not prove live provider integration or qualifying collection.

Setup records reference current source evidence and results rather than raw secrets. A successful adapter test has scoped provider/source references, observed outcome/time/environment and trust owner; it is not copied from a mock screen. Unknown/stale/missing capability proof remains explicit. Retest trigger follows actual dependency/version change; no invented universal test-age period. Failed publication/evaluation preserves previous valid source state and shows current owner/recovery.

## New gym and inheritance

Company presets/approved brand/role templates/document catalogue/policy defaults can prefill permitted local drafts by reference/version. Copying does not activate custom branding or give every staff member a new gym assignment. Address/timezone/resources/stock quantities/assets/local coach availability and billing/merchant applicability need deliberate location setup. All-gym membership rights include a future gym only if accepted plan explicitly permits it; never infer from the words all gyms.

Use [inheritance rules](gym-inheritance.json) to show inherited, overridden, local required, not applicable and invalidated values. Unset override inherits; Reset to company removes override rather than overwriting the company setting. Preview edits, retain original accepted/signed/issued versions, record actor/effective scope. Company default changes re-evaluate dependent gym setup and do not silently migrate financial identity, coach agreement, paid terms or staffing.
