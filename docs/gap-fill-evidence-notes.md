# Design Evidence Notes — 0.22

Research date: 7 November 2026. These primary references informed privacy/auth design precautions, not legal approval, chosen statutory ages or an assertion of provider support.

- ICO, Children's code default settings: https://ico.org.uk/for-organisations/uk-gdpr-guidance-and-resources/childrens-information/childrens-code-guidance-and-resources/age-appropriate-design-a-code-of-practice-for-online-services/7-default-settings/ . This supports the direction of high privacy by default. Applicability and exact consent/authority/data obligations still require appropriate review; no generic age threshold is hard-coded.
- NCSC, Multi-factor authentication for corporate online services: https://www.ncsc.gov.uk/collection/mfa-for-your-corporate-online-services . This informs stronger privileged access and use of an appropriate service/provider. It does not prove the actual Orb Gym auth project supports a given factor or recovery mode.

The product-specific choices to default junior public/social/direct-message exposure off and require owner/platform-admin MFA are conservative design decisions in this edition, not claims that those exact app rules are mandated verbatim by these sources. Actual technical/legal/content verification is separate.
