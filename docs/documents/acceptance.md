# Planned document/form acceptance

These supplement existing DOC/MEM/HR source checks and DATA/access/notification cases. They are not executed renderer/signature/provider tests.

| ID | Required outcome |
|---|---|
| DOC-AC01 | Each DCT type selects correct representation; upload, form, acknowledgement and actual signature never collapse into one completed flag. |
| DOC-AC02 | Missing reviewed PAR-Q/legal/safety wording blocks actionable publication/issue; draft preview is safe and labelled. |
| DOC-AC03 | Required stages permit blank-form input and file staging before answers/extraction exist; missing issue data still blocks issue. |
| DOC-AC04 | Typed variable picker rejects arbitrary code/query/cross-company source; unresolved required field is not AI-filled. |
| DOC-AC05 | Preview synthetic/current permitted data; source finance/signature/review values cannot be freehand overwritten by template author. |
| DOC-AC06 | Actual person/beneficiary/payer/signatory and independently verified guardian action rights remain distinct. |
| DOC-AC07 | Actual signer signs exact immutable issue; owner/admin cannot sign as recipient; multiple signers retain independent partial evidence. |
| DOC-AC08 | Read/download/scroll/delivery is not acknowledgement/signature; explicit decline remains safe owned outcome. |
| DOC-AC09 | Upload retains bytes/hash/provenance and actual original signature; unsupported OCR/preview cannot fabricate editable source or legal validation. |
| DOC-AC10 | Employee payslip/certificate/contract upload is not automatic payroll calculation or verified qualification; reviewer and expiry source retained. |
| DOC-AC11 | Template/profile/logo/rate changes leave issued/signed/accepted source snapshots intact. |
| DOC-AC12 | New applicability version affects only approved cohort/date/activity/renewal mode; no blanket annual PAR-Q or re-signing. |
| DOC-AC13 | Corrected unsigned issue withdraws obsolete request; signed replacement preserves original evidence and relationship. |
| DOC-AC14 | Document render cannot create charge, settle invoice or refund; receipt reprint/share creates no new sale/stock movement. |
| DOC-AC15 | Legal issuer independent of logo; white-label activation/source inheritance and default Orb brand applied correctly. |
| DOC-AC16 | Restricted HR/health/pay fields excluded from reception/search/preview/external notification; file reuse never broadens audience. |
| DOC-AC17 | Source review/signature/issue grants and individual denial rechecked at commit/file delivery; staff departure does not rewrite historical signer. |
| DOC-AC18 | Safe upload/scan/quarantine/progress/retry/unsupported states and real capability/format limits verified before live use. |
| DOC-AC19 | Composer handles keyboard block reorder, mobile Content/Fields/Preview, tablet bottom navigation and dirty/conflict state. |
| DOC-AC20 | Actual long tables/page breaks/font/logo/signature placement tested with selected renderer in preview and export; no clipped amounts. |
| DOC-AC21 | Printed/anonymous/member receipt destinations reflect actual authority; generic payslip notification contains no pay amount/attachment. |
| DOC-AC22 | AI extraction/drafting records source/uncertainty, cannot self-approve professional wording or obey uploaded instructions. |
| DOC-AC23 | Archive/retire/deletion/retention remain separate; supported protected link revocation does not falsely recall downloaded copies. |
| DOC-AC24 | Report export and communication layouts preserve canonical metric/event purposes and source freshness rather than alternate template calculations. |

Actual evidence must include DCT/source/template/issue/field versions, actor/authority, renderer/provider capability and observed success/denied/failure/correction outcomes. Catalogue validation alone proves none of the live behaviours above.
