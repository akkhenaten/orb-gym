## Representations and evidence

Interactive form: structured fields/conditional steps following an applicable approved schema. Store respondent, actual beneficiary, version, source requirement, typed answers and actual submission evidence. A health questionnaire cannot be invented from a generic text prompt. Emergency contacts are private fields, not a public profile.

Acknowledgement: explicit actual actor agrees they have received/read/acknowledged a specified applicable version with the appropriate intent. Document opened, email delivered, scroll position or class attendance is not acknowledgement. Do not label every acknowledgement a legal signature or infer consent to unrelated processing/marketing. Refusal/decline and unavailable signing remain truthful states with an owned follow-up.

Signed document: source issues immutable content/data/template/brand/legal issuer snapshot. Actual intended person or verified action-specific authorised signatory signs that exact issue with supported identity/intent/evidence mechanism. Platform admin/owner may administer and inspect but cannot sign as a customer or staff member. For multiple signatories, each role/identity/order/requiredness is part of the reviewed template; collect evidence separately and show partial signing. No counterparty is assumed from role label alone.

Protected upload: retain original file/hash/type/source/provenance and controlled metadata. An uploaded contract/payslip/certificate/invoice is not automatically composed, editable, signed by Orb or approved. If the file contains an existing signature, preserve it as original evidence with review/provenance; do not manufacture new signing timestamps or verification. OCR/extraction, if supported, is a source-labelled proposal with uncertainty and manual review. Unsupported preview/scan/type gives a safe state; no claim any PDF can become an exact editable form.

Issued financial snapshot: source module creates actual charge/invoice/credit/receipt only through authorised command. Documents may render the source but cannot create debt, collect cash or mark paid because a template preview says so. Print/share/reprint do not create a second sale. Credit note and refund confirmation are different source facts and labels. Existing issuer/brand/totals/history stay frozen.

Restricted HR/case record: note/meeting/case actor, factual content and audience are source-owned. Receiving a disciplinary note is not admitting its allegations; acknowledgement intent must be explicit and content/process reviewed. Staff viewing their own payslip is not access to colleagues' payroll. A report snapshot consumes the approved metric registry/as-of/current source-field scope, not an alternative template formula.

## Composer workspace

Documents opens a type-filtered template library with Draft/Review/Published/Archived and owning domain, version and content-readiness status. On desktop use field/block palette, editable document body and source/settings/properties panel when available content width permits. Preview is a distinct read-only rendered view; source editing remains source commands. Tablet/iPad/mobile retains bottom navigation and uses Content/Fields/Preview tabs plus accessible full-route properties. Preserve current template/draft on resize; no drag-only editing requirement.

Supported composed blocks: source-bound company/gym/legal issuer header, title/reference/date, reviewed static section, typed field group, source line table, protected attachment reference, actual signature/acknowledgement area and controlled footer. Reorder through keyboard-accessible Move up/down as well as optional drag. Only valid field types/requiredness/conditions allowed; no arbitrary JavaScript/SQL/template execution. Source financial/signature/review fields are locked bindings, not freehand author values. Show source tooltip, permissions, required stage and missing/denied errors.

Preview uses synthetic or explicitly permitted data and indicates draft/watermark and unresolved fields. Requiredness is stage-aware: an empty form shows input controls before answers exist; uploaded source can stage before reviewed extraction; source-derived field may resolve at issue. DCT required_payload_fields must be satisfied at applicable submission/review/issue, never demanded before input/upload can begin. Optional unknown values are omitted with appropriate clarity, never filled by AI guess. Required medical/legal/static content blocks must be approved before publishing an actionable form/agreement; a placeholder is not approved wording.

Complex documents/forms are addressable routes, not tiny confirmation modals. Save draft, preview, request review, publish, retire and create new version are separate commands under current grants. Dirty-state Save draft/Discard/Stay follows actual persistence. Conflict shows current diff and requires rereview; unknown save references original operation before retry. Canvas pagination/print layout, long tables, page breaks and signature placement must be verified with actual renderer/fonts. No pixel fidelity claim from schema alone.

## Content, fields and publication

Company Settings owns one published company/gym brand source; Documents consumes it. Default is Orb Gym until explicit white-label activation. Legal invoice/employment issuer is independently selected and frozen, not whichever gym logo is displayed. App/public page attribution remains exact Orb Gym - powered by orbsolutions.co.uk. Document/receipt attribution is an explicit controlled template element as the prior product rules specify; document layout cannot remove mandatory page attribution from the app.

Template author can edit approved static content within delegated workflow, but legal/safety/health/HR purpose-sensitive changes need the designated review gate and actual content evidence. Record source, reviewer, role, approval date/version, applicability, intended jurisdiction/activity and next review trigger where the company supplies it. This records review; it is not a compliance certification. No universal legal age, annual PAR-Q cadence, clinical decision, statutory retention or tax rule is invented.

Published version requires validated variables/required stages, purpose/audience, review-ready content, source module issue authority and output capability. Publication makes a template available to applicable future issues only. Material changes to existing people require DEC-GR-03 mode/cohort/effective date/reviewer/rights impact. Never silently demand every existing member sign a revised agreement just because someone edits a template. Signed/issued originals remain accessible within proper current rights and retention.

AI may help arrange/draft content or extract uploads when permitted, showing source and uncertainty. It cannot mark its own legal/clinical content approved, treat uploaded instructions as authority, recover unavailable original artwork or invent a real person's signature. Manual editing/upload remains available; missing AI capability is not a blocker to ordinary supported document routes.

## Issuance, completion and correction journey

Source requirement selects current applicable published template -> resolve actual person/beneficiary/payer/signatory/source version -> collect required data -> current privileged source review -> generate immutable issue/preview -> issue or request signature/acknowledgement -> capture actual evidence -> source review/eligibility gate -> secure delivery/history. Some steps are unnecessary for receipt/payslip/upload types; follow each DCT representation, not a forced universal signature wizard.

Evidence submission is not approval, signing is not payment, legal signature is not clinical clearance and a certificate upload is not verified qualification. Health evidence review uses membership.review_health_evidence and appropriate actual review process; ordinary house-rule acknowledgement does not require broad health visibility. Submitted sensitive answers stay off reception/shared screens and generic external notifications. Onboarding stays pending if required configured evidence is missing, with clear next owner/action rather than fabricated completion.

For correction, draft edits stay draft; issued unsigned corrections create a new issue and withdraw/supersede obsolete request. Signed corrections/new terms create an explicitly linked replacement/new agreement while preserving original issue/signature/hash/evidence. A profile/avatar/address/logo update cannot rewrite historic receipts/contracts. External file signature or underlying obligations cannot be silently undone by archive/delete. Redaction or eligible deletion uses reviewed retention/privacy process with source/audit, not a content editor overwriting legal history.

## Delivery, access and lifecycle

Protected library/file links use current role/record/field audience and underlying evidence rights; authorised reuse cannot broaden visibility. Template title/name/search/counts/preview must not leak private HR/health records. Issuer, intended signer, reviewer and recipient may be different; verify exact rights at each stage. Dismiss/read does not acknowledge/sign. Delivery, signature and source acceptance use the existing separate notification/state machinery.

Printed/customer receipt delivery uses the confirmed source snapshot; member-app destination only if the correct account has that receipt right. Anonymous sale can print/share to explicit permitted destination without inventing a member. Payslip/health/HR email notices use generic copy and a secure guarded link, not sensitive attached files by default. Actual supported channels/render/signing/upload scanning/format limits are inspected provider/runtime capabilities, not automatically available toggles.

Template retire stops future use as configured; archive retains required histories. Separate current access revocation from retention, eligible deletion and backup policy. Revoke future protected links/jobs as supported and test actual expiry/caches; already downloaded paper/file copies cannot be recalled by a role edit. Company staff departure changes their access and future sign/review ownership, not the document's historical actor identity.
